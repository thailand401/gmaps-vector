# Admin Dashboard - Copilot Instructions for New Tables

This document serves as a **checklist-based guide** for adding new tables and relationships to the admin dashboard. When a new table is created in Supabase, follow this workflow to automatically integrate it into the admin UI and API.

---

## Quick Reference: Adding a New Table

Each new table follows this pattern:
1. **Database & Models** — Define schema, create Pydantic model
2. **Service Layer** — Implement CRUD service class
3. **API Endpoints** — Create REST routes (GET, POST, PUT, DELETE)
4. **Admin UI** — Add list view, form, filters to dashboard

---

## Phase 1: Database Schema & Models

### Checklist

- [ ] **Confirm Supabase table exists** with columns defined
  - Verify table name matches convention: `plural_snake_case` (e.g., `users`, `driver_statuses`)
  - Note all column names, types, and constraints
  - Identify any foreign keys (relationships to other tables)
  - Document required vs optional fields

- [ ] **Create Pydantic model** in `backend/models.py`
  - Add a `*Base` model with essential fields (no IDs, timestamps)
  - Add a main model with optional ID, created_at, updated_at
  - Add `*Create` model (for POST requests)
  - Add `*Update` model with all fields optional (for PUT requests)
  - Add any specialized models for joined data (e.g., `IntentWithCategory`)

**Example Pattern (from intent.json schema):**
```python
class DriverStatusBase(BaseModel):
    driver_id: str
    status: str  # e.g., "active", "inactive", "on_break"
    notes: Optional[str] = None

class DriverStatus(DriverStatusBase):
    id: Optional[int] = None
    created_at: Optional[str] = None
    updated_at: Optional[str] = None

    class Config:
        from_attributes = True

class DriverStatusCreate(DriverStatusBase):
    pass

class DriverStatusUpdate(BaseModel):
    status: Optional[str] = None
    notes: Optional[str] = None
```

## Phase 2: Service Layer (CRUD Logic)

### Checklist

- [ ] **Create service file** `backend/services/{table_name}_service.py`

- [ ] **Implement CRUD methods:**
  - [ ] `get_all_{plural}(search=None, filters=None)` — List with optional filters
  - [ ] `get_{singular}_by_id(id)` — Fetch single record
  - [ ] `create_{singular}(model)` — Insert new record
  - [ ] `update_{singular}(id, model)` — Modify existing record
  - [ ] `delete_{singular}(id)` — Remove record
  - [ ] Add any specialized queries for relationships (e.g., `get_{plural}_by_{foreign_key}`)

- [ ] **Handle errors gracefully** with try-except and meaningful messages

**Template Pattern:**
```python
from config import supabase
from models import DriverStatus, DriverStatusCreate, DriverStatusUpdate
from typing import List, Optional

class DriverStatusService:
    @staticmethod
    async def get_all_driver_statuses(search: Optional[str] = None) -> List[DriverStatus]:
        try:
            query = supabase.table("driver_statuses").select("*")
            if search:
                query = query.ilike("status", f"%{search}%")
            result = query.execute()
            return [DriverStatus(**item) for item in result.data]
        except Exception as e:
            raise Exception(f"Failed to fetch driver statuses: {str(e)}")

    # ... other CRUD methods
```

**For relationships:**
```python
async def get_driver_statuses_by_driver(driver_id: str) -> List[DriverStatus]:
    """Fetch all statuses for a specific driver"""
    try:
        result = supabase.table("driver_statuses").select("*").eq("driver_id", driver_id).execute()
        return [DriverStatus(**item) for item in result.data]
    except Exception as e:
        raise Exception(f"Failed to fetch statuses: {str(e)}")
```

- [ ] **Create DELETE endpoint:**
  - [ ] `DELETE /api/{table_plural}/{id}` — Delete record

- [ ] **Add error handling:**

  ```javascript
  // Event listeners
  document.getElementById('addDriverStatusBtn').addEventListener('click', showAddDriverStatusModal);
  document.getElementById('driverStatusForm').addEventListener('submit', handleDriverStatusSave);

  // Functions
  function showAddDriverStatusModal() {
      appState.editingDriverStatus = null;
      UIComponents.clearForm('driverStatusForm');
      document.getElementById('driverStatusModalTitle').textContent = 'Add Driver Status';
      UIComponents.openModal('driverStatusModal');
  }

  window.editDriverStatus = function(status) {
      appState.editingDriverStatus = status;
      document.getElementById('driverId').value = status.driver_id;
      document.getElementById('driverStatus').value = status.status;
      document.getElementById('statusNotes').value = status.notes || '';
      document.getElementById('driverStatusModalTitle').textContent = 'Edit Driver Status';
      UIComponents.openModal('driverStatusModal');
  };

  window.deleteDriverStatus = function(statusId) {
      const status = appState.driver_statuses.find(s => s.id === statusId);
      deleteContext.type = 'driver_status';
      deleteContext.id = statusId;
      deleteContext.name = status?.status || statusId;
      document.getElementById('deleteMessage').textContent = `Are you sure you want to delete "${deleteContext.name}"?`;
      UIComponents.openModal('deleteModal');
  };

  async function handleDriverStatusSave(e) {
      e.preventDefault();
      const driverId = document.getElementById('driverId').value;
      const status = document.getElementById('driverStatus').value;
      const notes = document.getElementById('statusNotes').value;

      try {
          if (appState.editingDriverStatus) {
              await api.updateDriverStatus(appState.editingDriverStatus.id, {
                  driver_id: driverId,
                  status: status,
                  notes: notes || null,
              });
              UIComponents.showToast('Driver status updated', 'success');
          } else {
              await api.createDriverStatus({
                  driver_id: driverId,
                  status: status,
                  notes: notes || null,
              });
              UIComponents.showToast('Driver status created', 'success');
          }
          UIComponents.closeModal('driverStatusModal');
          await loadAllData();
      } catch (error) {
          UIComponents.showToast(`Error: ${error.message}`, 'error');
      }
  }
  ```

## Key Principles

1. **Naming Convention:**
   - Table names: `plural_snake_case` (e.g., `driver_statuses`, `vehicle_logs`)
   - API routes: `/api/{table_plural}` (e.g., `/api/driver-statuses`)
   - JavaScript IDs: `camelCase` (e.g., `driverStatusForm`, `driverStatusTableBody`)

2. **Error Handling:**
   - Always wrap API calls in try-catch
   - Use HTTPException for API errors
   - Show user-friendly toast notifications for errors

3. **Matrix Aesthetic:**
   - Reuse CSS classes: `.nav-btn`, `.btn`, `.data-table`, `.modal`
   - Don't create table-specific styling — keep it consistent
   - Apply color vars: `--accent-green`, `--accent-red` for status/priority indicators

4. **Async/Await Pattern:**
   - Use `async`/`await` consistently in FastAPI services and JavaScript
   - Handle errors at service level and return meaningful messages

5. **Form Handling:**
   - Always validate required fields
   - Clear forms after successful save
   - Close modals after success
   - Reload data to reflect changes

## Common Issues & Troubleshooting

| Issue | Solution |
|-------|----------|
| `CORS error when calling API` | Verify CORS middleware is enabled in `main.py` |
| `Toast notification doesn't appear` | Check that `toast` element exists in HTML with id `toast` |
| `Modal doesn't open` | Verify modal has class `modal` and corresponding button has `data-modal` attribute |
| `Data doesn't load` | Check browser console for error messages, verify Supabase table exists and has records |
| `Edit modal shows old data` | Clear form before opening with `UIComponents.clearForm()` |
| `Delete not working` | Verify foreign key constraints — may need to delete child records first |
